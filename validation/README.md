# Validation artifacts

This directory contains the evidence used to assess Ballistics Workbench's numerical models. It
keeps source facts, normalized inputs, reproducible scenarios, fitting definitions, and generated
reports separate. Fitted results are labelled as calibration evidence, not independent validation.

## Directory contract

- `sources/` contains redistributable numerical source data or metadata records for material that
  cannot be redistributed.
- `normalized/` contains SI-normalized inventories derived from source material. Every record must
  retain its source and transformation status.
- `scenarios/` contains solver-independent comparison inputs and expected values.
- `fitting/` contains reproducible fitting inputs and methods. Each observation is labeled as
  calibration or holdout.
- `reports/` contains machine-readable residuals produced from a scenario, fit, or benchmark.
- `schemas/` contains JSON Schema Draft 2020-12 contracts for those artifact families.
- `reference/` contains generators implemented separately from the production C++ integrator.

`manifest.json` is the authority for datasets, checksums, evidence levels, and the canonical report
set. Run `npm run validate:artifacts` after changing a validation artifact. Native comparison tests
write independent G7, atmosphere-property, manufacturer-table, adaptive-convergence, expanded
flight-matrix, and built-in effective-BC reports under the build directory. The benchmark tools add
the native timing and full-interaction reports. CI uploads these machine-dependent reports as
artifacts. The convergence report separates exact analytical step refinement and numerical
self-convergence from independent model conformance. The atmosphere report currently covers
CIPM-2007 density, NACA Report 1135 viscosity, and a limited published humid-air sound-speed matrix.

`npm run validation:docs` renders the checked-in `../docs/generated/VALIDATION_EVIDENCE.md` from the
manifest and six-load inventory. `npm run validation:summary` renders that file and
`build/validation/VALIDATION_SUMMARY.md` from all eight registered reports. The summary command fails
if a registered report is missing or carries a different model version. The matching `:check`
commands compare the generated text without writing it.

`reference/run-builtin-fits.mjs` validates the three registered definitions in `fitting/`, invokes
the real native calibration protocol, enforces residual-degree-of-freedom and confidence semantics,
and emits both a strict JSON report and deterministic Markdown. The checked-in
`../docs/generated/BUILTIN_FIT_EVIDENCE.md` must match that rendering byte for byte. The definitions
have no holdouts, so they remain `calibration_only` evidence.

`scenarios/independent-flight-matrix.json` is generated byte-for-byte by
`reference/generate-flight-matrix.mjs`. Its fixed-time 20-microsecond classical RK4 solver is
separate from the production adaptive integrator and covers G1, G7, tabulated Cd, sphere drag,
nonstandard atmosphere, three-dimensional wind/launch geometry, every built-in load, sight zeroing,
and MPBR. The atmosphere and sphere equations are independent transcriptions of the same declared
models. The comparison checks implementation and model-form conformance. It provides no external
empirical evidence.

Manufacturer publications are represented by small numerical transcriptions when the source
document's redistribution terms are not explicit. Their manifest records preserve the direct
locator, publisher, edition/date, retrieval date, units, normalization, rounding and uncertainty
limits, redistribution decision, and transcription checksum. A link plus a transcription is not
described as an archived source document.

Source qualification is stored separately from numerical content. `manufacturer_table` identifies
a manufacturer-controlled publication. `manufacturer_attributed_table` identifies data attributed
to a manufacturer but found only in another publisher's report. `secondary_publication` identifies
an independent publication or attribution. Generated reports retain this qualification and never
label a secondary source as primary evidence.

## Evidence levels

The ordered evidence-level definitions live in `manifest.json` and are included in the generated
evidence inventory. Artifact validation checks the full scale and rejects unknown load or report
levels. An artifact must not claim a higher level than its source data supports.
